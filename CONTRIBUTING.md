# Contributing

## Branches

| Branch | Purpose |
| --- | --- |
| `main` | Production. Protected — PRs only. |
| `develop` | Integration branch, deploys to staging. |
| `feat/<slug>` | New feature |
| `fix/<slug>` | Bug fix |
| `chore/<slug>` | Tooling, dependencies, docs |

## Commits

[Conventional Commits](https://www.conventionalcommits.org/):

```
feat(leases): add overlap validation on lease creation
fix(payments): use Decimal for late-fee calculation
docs(api): document the arrears endpoint
chore(ci): cache pip downloads in the backend workflow
```

Scopes: `auth`, `properties`, `units`, `tenants`, `leases`, `payments`, `maintenance`, `ui`, `db`, `ci`, `infra`.

## Pull requests

- One logical change per PR; keep them small enough to actually review.
- Fill in the PR template — the "how to test" section is not optional.
- CI must be green before review is requested.
- Schema changes must include the Alembic revision, and the revision must be read line by line, not merged as autogenerated.

## Code conventions

**Frontend**
- Server Components by default; `"use client"` only where interactivity requires it.
- No `fetch` in components — go through `src/lib/api/`.
- No `any`. If a type is genuinely unknown, use `unknown` and narrow it.
- Tailwind utilities in the markup; reach for `@apply` only for genuinely repeated patterns.

**Backend**
- Type hints on every function signature.
- Endpoints call services; services call repositories. Endpoints never touch the ORM.
- Pydantic schemas at the API boundary — ORM objects never cross it.
- `Decimal` for money, `timestamptz` in UTC for time.
- Raise domain exceptions from `core/exceptions.py`; let the handlers map them to HTTP.

## Tests

- New endpoints need at least a happy-path and an authorisation test.
- Business rules in `services/` need unit tests covering the boundary conditions, not just the obvious case.
- Tests run against a real PostgreSQL container, not SQLite — behaviour differs in ways that matter.
